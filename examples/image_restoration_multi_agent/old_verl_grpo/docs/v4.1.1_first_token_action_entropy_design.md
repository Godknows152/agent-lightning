# v4.1.1：重新 SFT 与合法动作首 Token 熵正则设计思路

> 文档日期：2026-08-01
>
> 适用范围：`examples/image_restoration_multi_agent/old_verl_grpo`
>
> 核心目标：先通过重新 SFT 使 16 个修复动作可以由首分支 Token 区分，再设计只在合法动作首 Token 集合上计算的可微分类熵正则

## 1. 文档目的与状态约定

v4.1.0 已经把决策点熵从“单个 Token 的全词表熵”改成“16 个完整动作字符串的序列分类熵”。这一修正解决了旧动作名共享首 Token 时无法区分动作的问题，但代价是每个决策点都要为所有合法动作建立 teacher-forcing 分支，真实 4GPU actor update 从约 64-72 秒增加到约 402-423 秒。

v4.1.1 的思路是从 SFT 数据源头改变模型侧动作词表：让每个合法动作都拥有唯一的首分支 Token。这样，训练时可以直接从当前 actor 对真实响应所做的同一次 forward 中取出 16/17 个合法动作首 Token 的 logits，构造动作分类熵，不再为完整动作串执行额外候选 forward。

## 2. 结论摘要

v4.1.1 的核心结论是：

1. **决策点不变**：仍然是每个 assistant thinking 中第一次写出该轮工具名的位置，而不是 `<parameter=action>` 中的正式工具调用位置。
2. **SFT 先解决首 Token 冲突**：通过 `A_...` 到 `P_...` 的模型侧动作名，使每个修复动作在实际决策上下文中具有唯一的首分支 Token。
3. **熵是 N 类分类熵**：不是“当前动作首 Token 对全词表的熵”，也不是“当前动作与其他动作的二分类熵”，而是把 16/17 个合法动作首 Token 的 logits 一起重新归一化后计算 Shannon 熵。
4. **不需要候选模型前向**：同一次 actor forward 已经计算决策位置对完整词表的 logits；只需在图中 gather 16/17 个合法 Token 的 logits。实现仍需修改 backend 的输出路径，但原则上不需要再次调用模型。
5. **保持可微**：`gather -> softmax/log_softmax -> entropy -> loss` 全部使用当前 actor 的 Tensor，禁止使用 rollout 旧概率、`detach()`、`item()` 或 `no_grad()`。
6. **动态合法集合**：第一轮为 16 个修复动作；允许 stop 后为 17 类。即使底层 schema 为复用上下文而始终带有 stop，熵候选集合仍应遵循实际 stop 可用规则。
7. **全回复熵暂时不动**：`entropy_coeff=0.005` 保持不变，v4.1.1 只替换决策点熵的计算对象，以便控制变量。
8. **系数不能机械照搬**：可以从 `0.002` 开始做连续性对照，但首 Token 熵和完整序列熵的梯度尺度不同，必须通过单 batch 梯度标定和系数消融确认。

## 3. 为什么需要 v4.1.1

### 3.1 v4 初版的问题：全词表熵不是动作熵

v4 初版在 thinking 中首次工具名位置计算：

```text
H_vocab = -sum_v P(v | prefix) log P(v | prefix)
```

这里的 `v` 遍历完整词表，包括普通语言、标点、XML 片段、非法工具名和合法动作 Token。提升 `H_vocab` 可能只是让模型在该位置更容易输出普通文字或虚构名称，不能证明合法工具之间的探索增强。

### 3.2 v4.1.0 的修正：完整动作串分类熵

v4.1.0 对每个合法动作字符串做 teacher forcing：

```text
S(a | p) = sum_i log P(a_i | p, a_<i)
q_sequence(a | p) = softmax_a(S(a | p))
H_sequence = -sum_a q_sequence(a | p) log q_sequence(a | p)
```

这个定义在语义上正确，也能区分旧 SFT 中首 Token 相同的 `Turbo-Rain` 和 `Turbo-Snow`。但每个决策点需要额外构造 16 个完整多模态前缀候选，保留全部候选 autograd graph，训练速度约慢 6 倍。

### 3.3 重新 SFT 后可以简化分类边界

如果 SFT 让 16 个动作在 thinking 中首次出现时就拥有不同首分支 Token，那么动作选择可以被显式编码为：

```text
同一个决策前缀
  -> A... 代表 real_esrgan
  -> B... 代表 scunet
  -> ...
  -> P... 代表 mb_taylorformer_dehaze
```

此时不再需要观察后续字符串才能区分动作。首分支 Token 本身就是 16 类动作变量的编码，因此可以直接在这 16 个 Token 的 logits 上计算分类熵。

这不是重新回到 v4 初版。二者的关键区别是：

| 方案 | 熵的支持集 | 是否等价于合法动作分类 |
| --- | --- | --- |
| v4 初版 | 完整词表约 15 万个 Token | 否 |
| v4.1.0 | 16 个完整动作字符串 | 是 |
| v4.1.1 | 16/17 个唯一动作首分支 Token | 在新 SFT 词表合同成立时是 |

该映射的单一配置源是：

```text
examples/image_restoration_multi_agent/config/tools.yaml
```

### 4.2 SFT 监督目标的变化范围

新 SFT 与原 SFT 的图像、prompt、thinking 模板数量、目标动作分布、LoRA 超参数和训练 epoch 基本不变。只修改模型可见的动作文本：

```text
旧 thinking:
I will select Turbo-Rain for targeted rain removal.

新 thinking:
I will select F_turbo_rain for targeted rain removal.
```

```xml
<tool_call>
<function=restore_image>
<parameter=action>
F_turbo_rain
</parameter>
</function>
</tool_call>
```

同一别名在每条 SFT target 中出现两次：thinking 中一次，XML action 参数中一次。schema enum 同样使用 A-P，确保监督输出不是“prompt 要求旧名称、GT 却输出新名称”的不一致训练。

### 4.3 SFT 数据和输出位置

当前已准备的独立路径为：

```text
data:   LlamaFactory/image_restoration_experts/data/first_token_actions/
config: LlamaFactory/image_restoration_experts/configs/first_token_actions_4gpu/
output: LlamaFactory/image_restoration_experts/outputs/qwen3_5_0731/
log:    LlamaFactory/logs/first_token_actions_4gpu/
```

四个专家串行训练；每个专家单独使用 GPU 0、1、2、3 做 4GPU DDP。每卡 batch size 为 4，梯度累积为 2，全局有效 batch size 为 32，与旧 2GPU 训练保持一致。

### 4.4 首 Token 唯一性不是只看首字符

动作名首字符 A-P 不同只是设计手段，真正需要验证的是 tokenizer 在实际上下文中的首分支 Token ID 不同。当前 Qwen3.5-9B tokenizer 已在以下三种上下文中验证为 17/17 唯一：

1. 独立动作字符串；
2. thinking 中动作名前存在空格；
3. XML `<parameter=action>` 后存在换行。

训练实现仍不能只依赖离线结论。每个决策样本都应使用真实 token boundary 和 `candidate_leading_text` 构造候选首 Token，并断言合法集合内 Token ID 唯一。若未来 tokenizer、模板或动作词表变化导致冲突，应明确报错或回退到完整序列评分，不能静默把两个动作合并成一类。

## 5. 决策点定义保持不变

### 5.1 真正使用的位置

v4.1.1 的决策点仍定义为：

> 在每个 assistant turn 的 `<think>...</think>` 内，模型第一次写出该轮工具名时，预测该工具名首分支 Token 的位置。

例如：

```text
The image contains dense haze. I will use N_focalnet_dehaze first.
                                             ^
                                  决策动作首 Token
```

正则使用的是箭头位置之前的因果前缀所产生的 next-token logits。

### 5.2 为什么不是工具调用参数位置

到达 `<parameter=action>` 时，thinking 已经写完，动作通常已经形成。参数位置主要是在结构化格式中复写选择。如果把正则移动到这里，模型可能只学会“在已经决定 N 之后如何写出 `N_focalnet_dehaze`”，而不是在观察图像和推理后如何在 A-P 之间保持适度不确定性。

工具调用参数仍然有两个用途：

1. 解析本轮实际尝试执行的动作；
2. 帮助在同一轮 thinking 中确认应定位哪个动作名。

它不是熵正则的新决策位置。

### 5.3 精确 Token 对齐

解码文本中的字符位置必须通过 tokenizer `offset_mapping` 映射回真实响应 Token。若动作字符落在一个带前导空格的 Token 内：

```text
token text = " N"
action char start 指向 N
candidate_leading_text = " "
```

所有候选都必须在同一个 Token 边界比较：

```text
tokenize(" " + A_real_esrgan)[0]
tokenize(" " + B_scunet)[0]
...
tokenize(" " + P_mb_taylorformer_dehaze)[0]
```

不能直接使用动作字符串脱离上下文时的第一个 Token ID，否则 BPE 的空格合并可能使探针与训练不一致。

## 6. 合法动作首 Token 分类熵

### 6.1 动态合法动作集合

设第 `t` 轮的合法动作集合为 `A_t`：

```text
第一轮且 stop 不可用：N_t = 16
允许 stop 后：          N_t = 17
```

第一轮最大原始熵：

```text
ln(16) = 2.7726 nats
```

后续轮最大原始熵：

```text
ln(17) = 2.8332 nats
```

合法集合应根据任务中的 stop 可用状态生成，而不是机械照抄底层复用 schema。第一轮即使上下文中的完整 schema 技术上含有 `stop`，只要 prompt 和任务协议禁止 stop，熵分类仍应使用 16 类。

### 6.2 从当前 actor logits 构造动作分数

设 `p` 是决策动作首 Token 之前的因果前缀，当前 actor 在该位置产生完整词表 logits：

```text
z(p) in R^V
```

对每个合法动作 `a`，根据真实前导文本得到唯一首 Token ID：

```text
c_p(a) = first_token(tokenize(candidate_leading_text + model_name(a)))
```

从完整词表 logits 中抽取动作分数：

```text
s(a | p) = z(p)[c_p(a)] / temperature
```

这里取的是所有合法动作首 Token 的分数，不只取实际采样动作的分数。

### 6.3 在合法动作集合内重新归一化

```text
q_first(a | p)
  = exp(s(a | p)) / sum_{b in A_t} exp(s(b | p))
  = softmax_{a in A_t}(s(a | p))
```

这一步的含义是：只在当前 16/17 个合法动作分支之间比较相对偏好。

它不是：

- 实际动作对“其他所有 Token”的二分类；
- 实际动作的 `-log q(action)`；
- top-p 截断后的 Sampling 分布；
- 完整词表 Policy 熵。

实际采样动作只是 `q_first` 中的一个类别。熵正则必须使用整个分类分布。

### 6.4 原始熵、归一化熵和有效动作数

```text
H_first(p) = -sum_{a in A_t} q_first(a | p) log q_first(a | p)

H_first_normalized(p) = H_first(p) / ln(N_t)

N_effective(p) = exp(H_first(p))
```

其中：

- `H_first` 单位为 nats；
- `H_first_normalized` 范围为 `[0, 1]`；
- `N_effective` 表示有效参与竞争的动作数；
- 建议加入 loss 的仍是归一化熵，以便 16 类与 17 类位置使用同一系数。

### 6.5 Loss 形式

首轮实现可以保持与当前接口连续：

```text
L_actor = L_GRPO
        + L_KL
        - beta_full * H_full_policy
        - beta_first * mean(H_first_normalized)
```

初始配置建议：

```text
beta_full  = 0.005  # 暂时保持不变
beta_first = 0.002  # 作为连续性起点，不代表已确认最优
```

## 7. 为什么原则上不需要额外模型前向

### 7.1 当前标准 actor forward 已经有什么

为计算当前策略 log probability 和全回复 Policy 熵，actor 本来就会对真实 prompt + response 执行 forward，并在每个响应位置得到完整词表 logits。决策位置所需的 A-P/stop logits 已经包含在其中：

```text
一次 actor forward
  -> 决策位置完整词表 logits z(p)
  -> gather 16/17 个合法动作首 Token logits
  -> q_first
  -> H_first_normalized
  -> actor loss
```

因此 v4.1.1 不需要像 v4.1.0 那样追加 16 个完整动作字符串，再为候选分支重新调用 Transformer。

### 7.2 “不需要额外 forward”不等于“不需要改代码”

当前 backend 通常在标准 forward 后只把 `log_probs` 和全词表 `entropy` 交给 loss，完整 logits 可能已经被丢弃。v4.1.1 仍需修改 engine：

1. 在 logits 尚在 autograd graph 中时定位“预测决策首 Token”的位置；
2. 立即 gather 16/17 个候选 Token logits；
3. 只把很小的 `[batch, 16/17]` Tensor 传给 entropy/loss；
4. 不长期保留整条序列的完整词表 logits。

正确的优化方向是“在同一次 forward 内尽早 gather”，而不是为了省代码再执行一次模型 forward。

### 7.3 不能只用当前 token 的 log probability

标准训练输出中的 `log_prob` 通常只保存真实响应 Token 的概率。它只提供：

```text
log P(actual_first_token | prefix)
```

但分类熵需要：

```text
logit(A), logit(B), ..., logit(P), [logit(stop)]
```

仅凭实际动作的一个 log probability 无法恢复其他 15/16 个动作的相对概率。因此必须在完整 logits 被释放前 gather 所有合法动作首 Token 分数。

## 8. 可微性

### 8.1 可微计算图

只要实现保持以下 Tensor 路径，可微性没有问题：

```text
current actor parameters theta
  -> logits z_theta(p)
  -> torch.gather(action_token_ids)
  -> log_softmax / softmax
  -> H_first_normalized
  -> -beta_first * H_first_normalized
  -> total_loss.backward()
  -> LoRA gradients
```

`gather` 对被选中的 logits 可微，softmax 和 Shannon entropy 同样可微。梯度会通过这些合法 Token 的输出 logits 回到 language model head、hidden states 和 LoRA 参数。

### 8.2 禁止的实现方式

以下做法会切断或错误替代梯度：

- 使用 rollout 阶段缓存的旧 logits；
- 在 `torch.no_grad()` 中重算动作分布；
- 对候选 logits 或 entropy 调用 `.detach()`；
- 用 `.item()` 取出 Python 数值后再拼回 loss；
- 只对实际采样动作计算 `-log q(action)` 并把它称为分布熵；
- 使用 top-p 之后的 Sampling 概率替代当前 actor Policy logits。

### 8.3 非法 Token 不接收直接熵梯度是有意设计

`q_first` 只由合法动作首 Token 的 logits 构造，因此非法 Token 不在这个熵项的直接支持集中。这样可以避免 v4 初版的全词表扩散把探索压力施加到任意普通词或虚构工具名上。

全回复熵仍然保留，所以完整 loss 里依然存在全词表探索压力。v4.1.1 第一轮实验按既定决策不修改 `entropy_coeff=0.005`，但必须联合监控非法动作指标。

## 9. 与完整动作串熵的关系

### 9.1 两种分布并不数学恒等

完整序列分数为：

```text
S_sequence(a | p)
  = log P(first_token(a) | p)
  + log P(suffix(a) | p, first_token(a))
```

v4.1.1 只使用第一项。因此，即使首 Token 唯一：

```text
q_first(a | p) != q_sequence(a | p)
```

在一般情况下仍然成立。后缀置信度差异会改变完整序列排序。

### 9.2 为什么 v4.1.1 仍然合理

重新 SFT 的目标不是让首 Token 近似完整字符串概率，而是明确把动作选择变量编码到第一个分支上：一旦生成 A-P 中某个首 Token，动作身份已经确定，后续字符主要负责完成该名称。

因此 v4.1.1 正则的是：

> 模型在进入某个动作名称分支之前，对 16/17 个动作分支的选择不确定性。

v4.1.0 正则的是：

> 模型完整写完每个合法动作名称的相对序列概率。

二者应通过探针对照，而不是直接假设相等。

### 9.3 实施前必须做的相关性验证

加载新的 0731 SFT LoRA 后，对同一批真实决策前缀同时计算：

```text
H_first_normalized
H_sequence_normalized
rank_first(a)
rank_sequence(a)
```

至少检查：

1. 实际生成动作在两种分布中的 rank 是否一致；
2. 两种熵在样本间的 Spearman 相关性；
3. 是否存在首 Token 很有把握、但名称后缀概率极低的动作；
4. thinking 与 XML 两个位置是否都稳定输出同一别名；
5. 是否还出现旧名称或 canonical 名称。

若新 SFT 后缀完成仍不稳定，则说明“首 Token 已承载动作选择”的训练目标没有真正学成，不能直接用首 Token 熵替代完整序列熵。

## 10. 全轨迹覆盖与轨迹级公平

根据最终实现要求，v4.1.1 直接覆盖整条轨迹，而不是只计算首个可定位决策点：

1. 解析每个 assistant turn 的独立 thinking 和工具调用；
2. 在每轮 thinking 中定位首次模型侧动作名；
3. 第一轮计算 16 类，stop 可用后计算 17 类；
4. 对每个成功定位的决策点都计算归一化首 Token 熵；
5. 先对同一轨迹内的全部有效决策点求均值，再对全局有效轨迹求均值；
6. 记录决策点 found rate、有效轨迹率、每条有效轨迹的决策点数和 collision count。

设轨迹 `i` 有 `K_i` 个有效决策点，实际 loss 使用：

```text
H_trajectory_i = sum_j H_normalized_ij / K_i
H_batch = sum_i H_trajectory_i / N_valid_trajectories
```

没有有效决策点的轨迹不进入熵均值，但会进入覆盖率统计。不能使用“全部决策点熵之和 / 全部决策点数”，否则长轨迹会因为决策点更多而获得更大的正则权重。

## 11. 合法性假设与实验边界

### 11.1 合法集合归一化的数学盲区

与完整序列合法动作熵一样，首 Token 合法动作熵只比较合法集合内部的相对分布。即使模型给非法 Token 很高概率，合法集合内部重新归一化后的熵仍可能很高。

### 11.2 v4.1.1 第一轮不增加合法性损失

本项目的起点是经过严格 schema SFT 的模型。新 SFT 又显式监督 A-P 动作名，理论上模型应主要在合法动作分支中选择。为了控制变量，v4.1.1 第一轮实验采用以下边界：

- 不增加 constrained decoding；
- 不增加合法概率质量 loss；
- 不修改非法动作 penalty；
- 不修改全回复熵系数；
- 只替换决策点熵的动作表示和计算路径。

这是基于 SFT 起点的工程假设，不是说数学盲区不存在。必须继续记录：

```text
restoration_penalty/invalid_restoration_action_count
restoration_penalty/unknown_tool_name_count
actor/decision_point_legal_first_token_mass  # 建议新增，仅监控
```

其中合法首 Token 总概率质量可以只作为监控指标：

```text
M_legal(p) = sum_{a in A_t} P_vocab(c_p(a) | p)
```

第一轮不把它加入 loss。若非法动作持续升高，再独立设计 legality loss 消融。

## 12. 系数设计

### 12.1 合理系数可以控制均匀化，但不能只看数值相同

持续最大化 `H_first_normalized` 的单独最优解是 16/17 类均匀分布。实际 actor loss 还有 GRPO 质量梯度、KL 和全回复熵，因此较小系数可以只提供反塌缩压力，而不必把策略推成均匀随机。

不过，`beta_sequence=0.002` 和 `beta_first=0.002` 只表示 loss 数值系数相同，不表示参数梯度强度相同。首 Token 熵路径更短，梯度可能比完整序列熵更直接。

### 12.2 建议的标定步骤

在不执行 optimizer step 的固定 batch 上分别计算：

```text
||grad(L_GRPO)||
||grad(beta_full * H_full)||
||grad(beta_first * H_first_normalized)||
```

同时记录各项 loss 数值。然后再决定正式系数。

首轮系数网格建议：

| 组别 | `beta_first` | 目的 |
| --- | ---: | --- |
| A | `0` | 0731 SFT 新起点基线 |
| B | `0.0005` | 弱探索压力 |
| C | `0.001` | 中等探索压力 |
| D | `0.002` | 与 v4.1.0 数值连续性对照 |

全组保持：

```text
entropy_coeff = 0.005
temperature = 1
top_p = 1
```

不要只根据单步熵值选择系数。至少共同观察纯图像 reward、非法动作、KL、grad norm、tool-choice entropy 和 actor update 时间。

1. v4 初版首 Token 全词表熵；
2. v4.1.0 完整动作字符串归一化熵；

## 15. 训练实现草图

### 15.1 数据准备

对每个选中的决策点准备：

```text
decision_point_prediction_index
legal_first_token_ids[16 or 17]
legal_action_mask[16 or 17]
decision_point_found
stop_available
```

### 15.2 同一次 forward 内 gather

伪代码：

```python
raw_output = actor(**model_inputs, use_cache=False)
logits = raw_output.logits / temperature

decision_logits = gather_prediction_positions(
    logits,
    decision_point_prediction_index,
)

legal_logits = decision_logits.gather(
    dim=-1,
    index=legal_first_token_ids,
)

legal_logits = legal_logits.masked_fill(~legal_action_mask, -torch.inf)
legal_log_probs = torch.log_softmax(legal_logits.float(), dim=-1)
legal_probs = legal_log_probs.exp()
raw_entropy = -(legal_probs * legal_log_probs).sum(dim=-1)
normalized_entropy = raw_entropy / torch.log(num_legal_actions.float())
```

实现时应在完整 logits 释放前立即 gather，并只保留 `legal_logits`。上面伪代码用于表达数学路径，不代表可以忽略 remove-padding、nested tensor、序列移位、data parallel 和 mixed precision 细节。

### 15.3 分布式归一化

loss 应先做本地逐轨迹决策点均值，再按全局有效轨迹数归一化，并处理以下边界：

- 某个 data-parallel rank 没有找到决策点；
- 整个 global batch 的有效决策点数为 0；
- 16 类与 17 类样本在同一 batch；
- 不同轨迹长度和不同决策点数量；
- found mask 为空但仍需保持可执行的零梯度图。

每个 data-parallel rank 先累加本地有效轨迹的轨迹均值，再除以全局有效轨迹数，并使用与现有 FSDP loss 一致的 DP 缩放。某个 rank 没有有效轨迹时仍返回连接当前 actor 计算图的零 loss。

## 18. 风险与应对

| 风险 | 现象 | 应对 |
| --- | --- | --- |
| 首 Token 合同未真正学会 | thinking 仍输出旧名称或普通文字 | 停止 GRPO，先修 SFT 数据/训练 |
| 上下文 BPE 冲突 | 某些样本 16/17 类 Token ID 重复 | runtime assert；回退完整序列评分或跳过并记录 |
| 首 Token 与完整序列偏好不一致 | rank 相关性低、后缀完成不稳定 | 保留 v4.1.0，重新强化 SFT 后缀监督 |
| 系数导致均匀随机 | 熵接近 1、reward 下降 | 降低 `beta_first`，再考虑调度或熵下限 |
| 合法集合外概率升高 | illegal action 增长、legal mass 下降 | 先降低全回复熵/首 Token 系数做消融，再单独设计 legality loss |
| 实现意外增加 forward | update 时间仍接近 400 秒 | 增加 forward 计数测试，检查是否复用了标准 actor forward |
| 指标语义混用 | 新旧 SwanLab 曲线被直接拼接 | 使用新指标名，并记录 entropy type 与代码版本 |
| 长轨迹权重过大 | 多轮轨迹获得更多熵增益 | 轨迹内平均或每轨迹均匀采样一个轮次 |

## 19. 实施顺序

建议严格按以下顺序推进：

1. **训练 0731 SFT LoRA**，不要在 adapter 不存在时启动 GRPO；
2. **运行真实探针**，验证格式、别名、首 Token 唯一性和 `H_first/H_sequence` 关系；
3. **实现独立数学函数**，输入 `[batch, N]` legal logits，输出原始/归一化熵；
4. **[已完成] 修改决策点数据准备**，为每条轨迹的全部 assistant turn 生成 legal first-token IDs；
5. **[已完成] 修改当前训练 backend**，在标准 actor forward 内 gather legal logits；
6. **[已完成] 接入 loss 与新指标名**，保持全回复熵不变，并执行轨迹内均值；
7. **[部分完成] 完成可微性、分布式、全轨迹检测和入口测试**；真实 GPU forward 计数与 probe 数值 parity 仍需在单 batch 训练验证中完成；
8. **运行单 batch 梯度标定**；
9. **运行 0731 无决策熵基线和系数短程消融**；
10. **用全轨迹实现运行短程对照，并核对按轮次覆盖率与轨迹级均值**。

## 20. 最终设计边界

v4.1.1 不是简单地“把完整动作串熵换回首 Token 熵”。它成立依赖一个新的、由 SFT 主动建立的动作表示合同：

```text
每个合法动作
  <-> 一个模型侧动作名
  <-> 在真实决策上下文中唯一的首分支 Token
  <-> 一个 canonical runtime 动作
```

在这个合同成立后，合法动作首 Token 分类熵才真正表示动作选择空间，而不是完整词表语言不确定性。它的主要工程价值是：保留 v4.1.0 “只在合法动作之间正则化”的语义，同时移除 16/17 个完整动作字符串 teacher-forcing 候选前向。

当前最重要的边界是：

- 新 SFT 数据、命名和 GRPO 边界已经准备好；
- 四专家新 SFT LoRA 已训练完成并通过入口预检；
- 首 Token 合法动作熵已经以独立 v4.1.1 配置进入训练代码；
- 每条轨迹的全部有效决策点都会计算，loss 先做轨迹内均值；
- 全回复熵系数暂时保持不变；
- 第一阶段必须用 0731、`beta_first=0` 基线隔离重新 SFT 本身的影响；
- 在探针和训练数值对齐之前，不应把首 Token 熵结果作为 GRPO 设计结论。

因此，v4.1.1 的下一项实际工作不是立即修改 loss，而是先完成 0731 SFT，并用真实模型验证“动作选择已经被稳定编码到唯一首分支 Token”这一前提。
